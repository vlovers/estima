# Security policy

## Reporting vulnerabilities

Do not publish vulnerabilities, credentials, tokens, user data or exploit instructions in public issues or pull requests.

Use the repository's GitHub **Report a vulnerability** / private vulnerability reporting feature if enabled. If it is unavailable, contact the maintainer using a previously established private channel. Do not post sensitive details publicly to establish contact.

A useful report includes affected commit/version, a minimal safe reproduction, impact, and remediation suggestions where available. Redact secrets and customer data.

## Scope

Estima handles authentication, AI-assisted estimates, project data and a PostgreSQL-backed API. Reports involving authorization boundaries, tenant isolation, token handling, injection, dependency or deployment security are particularly relevant.

## Supported versions

The project is under active development. Security fixes target the latest development branch; older versions have no guaranteed support.

## Response

No fixed response-time or disclosure SLA is promised. Maintainers will coordinate disclosure after assessment and remediation when feasible.
